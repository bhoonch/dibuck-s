# 법정점검 대장 모듈 — 개발 프롬프트

> 이 문서를 새 세션에 그대로 주고 "이 프롬프트대로 구현해줘"라고 하면 된다.
> 구현 전 AGENTS.md와 아래 "먼저 읽을 파일"을 반드시 읽는다.
> **안전교육일지 모듈(`/modules/safety-training`)이 가장 가까운 최신 견본이다** —
> 이행 현황 카드, 법정 값 상수화, 증빙 스냅샷, 크론 회차 키까지 같은 문법을 쓴다.
> 단, 이 모듈은 **LLM을 쓰지 않는다** — AI 모듈이 아니라 주기 엔진 모듈이다.

## 1. 목표

소장 인력 부족 이유 2위(49.7%)인 **법정 의무점검·행정서류** 고통을 없앤다. 고통은 세 겹:
① 소방·승강기·저수조·전기·놀이시설의 법정 주기가 전부 달라 머리·엑셀로 관리하고,
② 놓치면 과태료가 소장 개인 책임이며, ③ 점검을 해도 일지 작성 + 대장 정리 + 감사
서류철 편철을 삼중으로 한다.

한 줄 정의: **"주기는 앱이 세고, 기록은 한 번만 입력하고, 감사 서류철은 자동으로
쌓인다."** 최종 산출물은 기존 포지셔닝 그대로 "지자체 감사 나와도 3분 만에 뽑는
서류철"이다. 로드맵 4번(법정 의무 이행 증빙 = 기존 5위+8위 병합)의 남은 절반 —
교육일지 절반은 `safety-training`으로 이미 출시됐다.

## 2. 확정된 설계 결정 (재논의 불필요)

- **모듈은 예약돼 있다.** `prisma/seed.ts`의 `id: "facilities"`(설비 이력관리, Wrench,
  `/modules/facilities`, 월 20,000원, `isActive: false`). **재정의한다** — 이름을
  "법정점검 대장"(가칭, 구현 세션에서 사용자 확인)으로, 설명을 실제 동작에 맞게 바꾸고
  완성 시 `isActive: true`. 가격 20,000원 유지. 모듈 id는 바꾸지 않는다(라우트·아이콘
  매핑이 물려 있다).
- **데이터는 3계층**: 카탈로그(상수 파일) → `InspectionItem`(단지별 활성 항목+앵커일)
  → 점검 기록(`Document`). 카탈로그를 DB에 넣지 않는 이유 — 법정 주기는 상품 정책이
  아니라 법이 정하는 값이라 코드 개정으로만 바뀌어야 한다(safety-training 법정
  시간표와 같은 원칙).
- **다음 도래일은 저장하지 않는다** — `nextDue(item, today)` 순수 함수로 열 때마다
  계산. 저장하면 갱신 크론이 필요해지고 어긋날 자리가 생긴다(체험 만료를 `trialEndsAt`
  시점 비교로 푼 것과 같은 판단).
- **점검 기록 = Document** — 새 type `"inspection"`, `docNoPrefixes`에 `점검` 추가.
  meta에 항목명 스냅샷 — 항목을 나중에 고쳐도 지난 증빙은 불변(교육일지 참석자
  스냅샷과 같은 증빙 원칙). 완료 저장 시 `InspectionItem.lastDoneAt` 자동 갱신
  (조건부 updateMany — 입구 검사 규칙) → 다음 도래일이 저절로 굴러간다.
- **A4 점검일지는 결정적 코드 — LLM을 부르지 않는다.** 값을 채우는 정형 문서라 작문이
  필요 없다(공고문·후속 문서와 같은 판단, 건당 비용 0원). `ANTHROPIC_API_KEY` 게이트
  불필요.
- **법 조문 해석은 코드가 하지 않는다** — "우리 단지가 종합점검 대상인가"를 코드가
  판정하지 않는다. 설정 마법사가 쉬운 말로 묻고("스프링클러가 설치되어 있나요?")
  사용자가 켜고 끈다. 판정 책임을 앱이 지지 않되 힌트는 최대한 준다.
- **`lastDoneAt`이 비어 있으면 판정에서 빼지 않고 "기준일 입력 필요"로 표시한다** —
  교육 크론의 `hiredAt` 규칙과 반대인 이유: 교육은 안 넣으면 대상이 아닌 게 자연스럽지만,
  점검은 켜놓고 기준일이 없으면 주기를 셀 수 없다는 사실 자체를 알려야 한다.
- **크론 알림 + 자동 작업지시**: `/api/cron/inspection` — `CRON_SECRET`, **GET·POST
  둘 다**(AGENTS.md), 하루 1회. 도래 D-{leadDays}에 작업지시 문서(status pending,
  dueDate=도래일) 생성 → 홈 할 일 위젯 "점검 예정"(이미 자리가 비워져 있음, 컨벤션
  type+status+dueDate) + 인앱 알림(`Notification.type`에 `"inspection_due"` 예약됨).
  D-7 알림 1회 더, 기한 경과(지연) 시 소장 메일(`trySend` — 과태료 위험은 접속 안
  해도 닿아야 한다, 5.5 결정과 동일 논리).
- **중복 방지는 회차 키** `inspection_{itemId}_{dueYmd}_D30` — training 크론과 동일
  문법. 판정은 "당일"이 아니라 "임계를 처음 넘긴 때"라 크론이 하루 빠져도 안내가
  사라지지 않는다.
- **범위 밖 (다시 검토하지 말 것)**: K-apt 이중입력 해소(공개 API 미확인 — S-APT
  보류와 같은 판단, 병행 입력 단지가 실제로 나타나면 항목별 복사 버튼) / 지적사항 →
  수리 기안 자동 파생(approvals 크로스셀 — meta.findings가 데이터로 남으니 나중에
  붙이기 쉽다) / 대상 여부 자동 판정 / LLM.

## 3. 카탈로그 (상수 파일 — `src/lib/inspection/catalog.ts`)

항목 스키마:

```ts
{
  key: string; label: string;
  category: "소방" | "승강기" | "급수·위생" | "전기" | "시설" | "기타";
  legalBasis: string;   // "소방시설법 제22조" — 확실한 것만, 고시 호수·개정 연도 금지(기존 규칙)
  cycle: { type: "MONTHLY" | "QUARTERLY" | "SEMIANNUAL" | "ANNUAL" | "YEARS"; n?: number };
  executor: "SELF" | "VENDOR" | "AGENCY";  // 자체 / 유지관리업체 / 검사기관
  leadDays: number;     // 준비 리드타임 — 업체 예약·기관 접수 필요 항목은 30, 자체는 7
  applicableHint: string; // "승강기가 있는 단지" — 마법사 질문에 사용
}
```

초기 항목 후보 — ⚠️ **아래 주기·근거는 계획 시점(2026-08-05) 지식이다. 구현 착수 시
법령 원문(law.go.kr) 재확인이 Phase 0이고, safety-training 부록과 같은 출처 표를
이 문서 부록에 채워 넣는다.**

## 4. 스키마

```prisma
model InspectionItem {
  id         String    @id @default(cuid())
  tenantId   String
  presetKey  String?   // 카탈로그 키. null = 사용자 정의
  name       String    // 스냅샷 — 카탈로그 개정에도 기존 항목 불변
  legalBasis String
  cycleType  String
  cycleN     Int?
  leadDays   Int       @default(7)
  lastDoneAt DateTime? // 앵커일 — 마지막 실시일. 완료 기록 시 자동 갱신
  vendor     String?   // 담당 업체명·연락처 자유 텍스트
  active     Boolean   @default(true)
  tenant     Tenant    @relation(...)
  @@index([tenantId])
}
```

- ⚠️ **tenant 탈퇴 purge(`src/lib/tenant-deletion.ts`)에 deleteMany 추가** —
  TrainingStaff 때와 같은 함정.
- Document 저장: `{ moduleId: "facilities", type: "inspection", dueDate(작업지시),
  meta: { itemId, itemName, doneAt, result: "정상" | "지적사항", findings, actions,
  vendor, cost, ... } }`. 첨부는 기존 문서 첨부 인프라(quote-attachment)로 성적서·
  검사필증 PDF·사진.

## 5. 주기 엔진 (순수 함수 — `src/lib/inspection/schedule.ts`)

- `nextDue(item, today)` — 앵커일 + 주기. 월(같은 날, 말일 잘림 — billing의
  `billingDay` 교훈), 분기, 반기, 연, N년. **KST 기준**(`ymdKst` 축 — 법정 기한은
  KST 벽시계다).
- 상태 판정 4종: `ok`(주기 내) / `imminent`(D-leadDays 이내) / `overdue`(경과) /
  `needsAnchor`(lastDoneAt 없음).
- 크론 회차 판정(D-lead·D-7·지연, "임계를 처음 넘긴 때").
- **전부 순수 함수 + `npx tsx inspection.test.ts`(DB 불필요)** — 날짜 계산 오류가 곧
  과태료인 모듈이라 엔진을 화면보다 먼저 테스트로 굳힌다. 반기·연·N년 경계, 윤년
  2/29, 말일(1/31 + 1개월), KST 자정 경계를 반드시 포함.

| `/modules/facilities/new?item=` | 기록 작성 — 기본값 전부 채워진 채 시작(실시일=오늘, 업체=항목 vendor). 결과 라디오(정상/지적사항)·지적 내용·조치·비용·첨부 |
| `/modules/facilities/[docId]` | A4 점검일지 미리보기·인쇄·첨부 목록. 작업지시 문서면 [기록 작성] 버튼 |
| `/modules/facilities/binder` | **감사 서류철** — 연도 선택 → 항목 × 월 매트릭스(✓=문서 링크, 공백 도래분=빨강). **safety-training 교육일지 행도 함께 표시** — 로드맵 "5위+8위 병합"이 이 화면에서 완성된다. [전체 인쇄] |

편의성 원칙(이 모듈의 존재 이유): 법정 주기를 **몰라도 되고**, 완료 기록 한 번이
일지(A4)·대장(문서함)·서류철(binder) 세 가지 뷰가 되며, 소장이 바뀌어도 항목·주기·
업체·이력이 단지에 남는다(인수인계 누락 방지 — 숨은 셀링포인트).

## 7. A4 점검일지 서식 (결정적 코드)

```
제목: 법정 점검·검사 실시 기록          (문서번호는 상단 표 안)
[정보 표] 문서번호 / 점검 항목 / 근거 법령 / 실시일자 / 수행(자체·업체명) / 비용
[결과] 정상 or 지적사항 — 지적 내용·조치 계획 개조식
[첨부] 성적서·검사필증 목록
[하단] "위와 같이 법정 점검을 실시하였음." + 작성일 + 작성자 + 관리사무소장 확인란
```

- 책상 증빙 문서 — 활자는 기안서 축(본문 11.5~12pt), `gian-paper.tsx` 괘선 문법 재사용.
- 헤드리스 실측(printToPDF pageRanges — 공지문 검증법) 1장 판정.

## 10. 수용 기준

1. 마법사 질문에 답하고 마지막 실시일만 넣으면 — 법정 주기를 하나도 몰라도 —
   현황판에 전 항목 D-day가 나온다.
2. 기록을 완료 저장하면 `점검-YYYY-####` 채번 + `lastDoneAt` 갱신 + 다음 도래일이
   자동으로 굴러간다. 항목을 나중에 수정해도 지난 기록의 meta는 불변.
3. 크론이 D-{leadDays}에 작업지시 문서를 만들고 홈 할 일 위젯 "점검 예정"에 뜬다.
   같은 회차에 두 번 만들지 않는다(회차 키). 크론이 하루 빠져도 다음 실행에서 잡힌다.
4. 기한 경과 항목은 현황판 빨강 + 인앱 알림 + 소장 메일(SMTP 없으면 조용히 생략,
   `trySend`).
5. 감사 서류철이 연도별 항목 × 월 매트릭스를 그리고, 완료 칸은 문서로 링크되며,
   교육일지 행이 함께 나온다. 미이행 도래분이 빨갛게 보인다.
6. 날짜 엔진 순수 함수 테스트에 반기·연·N년 경계, 윤년, 말일 잘림, KST 경계 포함.
7. LLM 호출이 코드에 없다. `ANTHROPIC_API_KEY` 없는 환경에서 전 기능이 돈다.
8. tenant 탈퇴 purge가 InspectionItem을 지운다(테스트).
9. 법정 주기·근거 값은 `catalog.ts` 한 곳에만 있다.
10. 미구독은 서버 액션 입구 차단. 크론은 **구독 단지만** 작업지시를 만든다
    (미구독 단지에 알림이 가면 거짓 약속).
11. 시드 모듈 이름·설명이 실제 동작과 일치(과장 금지 — "알림"은 크론이 실제로 보내는
    범위만 서술).
