# 산업안전보건 교육일지 자동완성 모듈 — 개발 프롬프트

> 이 문서를 새 세션에 그대로 주고 "이 프롬프트대로 구현해줘"라고 하면 된다.
> 구현 전 AGENTS.md와 아래 "먼저 읽을 파일"을 반드시 읽는다.
> **공지문 모듈(`/modules/notice`)이 가장 가까운 최신 견본이다** — 초안→완성 채번,
> 카드 그리드 선택, LLM 호출, A4 실측까지 같은 문법을 쓴다.

## 1. 목표

관리사무소가 산업안전보건법상 의무인 근로자 안전보건교육을 실시하고 **증빙(교육일지)을
남기는 일**을 자동화한다. 종류·주제를 고르고 참석자를 체크하면 강사가 읽으며 교육할 수
있는 수준의 교육 내용까지 채워진 일지가 완성된다. 미실시 반기는 앱이 먼저 알려준다.
과태료 대비 문서라 **기록의 불변성**(완성 후 참석자 스냅샷)이 중요하다.

## 2. 확정된 설계 결정 (재논의 불필요)

- **모듈은 예약돼 있다.** `prisma/seed.ts`의 `id: "safety-training"`("산업보건 교육일지 —
  법정 교육 기록과 기한 알림", HardHat, `/modules/safety-training`, 월 10,000원,
  `isActive: false`). 완성 시 true 전환 + 설명 문구가 실제 동작과 일치하는지 확인.
- **교육 종류 3가지**: 정기교육 · 채용 시 교육 · 관리감독자 교육. 특별교육·작업내용
  변경 교육은 범위 밖(요청 시 다음 단계).
- **직원 명부는 모듈 전용 테이블** `TrainingStaff { id, tenantId, name, position(직종:
  사무·기전·경비·미화·기타), office(사무직 여부 boolean), active }`. 앱 계정(User)과
  연결하지 않는다 — 교육 대상 대부분(기전·경비·미화)이 계정이 없다. 단, 명부 관리
  화면에 "앱 직원 불러오기" 버튼 하나(이름·직책 복사). ⚠️ 새 테이블이라도 Document를
  참조하지 않으므로 Cascade 함정은 없지만, **tenant 탈퇴 purge(`tenant-deletion.ts`)에
  deleteMany 추가**를 잊지 말 것.
- **교육 회차 = Document** — 새 type `"safety_training"`, `docNoPrefixes`에 `교육` 추가.
  **채번은 완성 시점**(공지문 `7e2653b` 규칙 그대로): 생성=draft·번호 없음 →
  [일지 완성]이 assignDocNo+조건부 updateMany. 미완성 초안 폐기=하드 삭제,
  완성본 폐기=void. 초안엔 인쇄 숨김.
- **참석자는 문서 meta에 스냅샷** `attendees: [{ name, position }]` — 명부를 나중에
  고쳐도 지난 일지는 불변(증빙 원칙). 참석자에게 추적할 상태가 없으므로 별도
  테이블을 만들지 않는다(독촉장 DunningEntry와 다른 점).
- **기한 알림은 결정적 코드** — 모듈 홈에서 판정한다(크론·저장값 없음, 열 때 계산):
  이번 반기에 완성된(final) 정기교육 일지가 사무직·그 외 각각 있는가, 올해 관리감독자
  교육이 있는가. 없으면 AttentionCard로 "반기 마감 N일 전" 안내. 홈 할일 위젯 연동은
  기존 컨벤션(`type:"contract"`+dueDate)이 계약 전용이므로 **이번 범위 밖** — 모듈
  홈 카드가 1차 알림이고, 인앱 알림(notifyTenant)도 만들지 않는다(크론 없이는 거짓
  약속이 된다).
- **LLM은 교육 내용만 쓴다** — 일시·장소·시간·강사·참석자는 전부 폼 값 그대로.
  gian/notice-ai 패턴(Sonnet 5·structured outputs·프롬프트 캐싱·`aiEnabled` 게이트).
- **A4는 책상 증빙 문서** — 활자는 기안서 축(본문 11.5~12pt). 게시물(14pt)이 아니다.
  읽는 거리 규칙([[dibuck-typography-and-layout]]).

## 3. 법정 값 (2026-08 조사 — 시행규칙 별표 4·5 기준)

**법정 시간·주기는 상수 한 곳에 모아 둔다**(개정 대비). 값:

| 종류 | 대상 | 시간 |
|---|---|---|
| 정기교육 | 사무직 종사 근로자 | **매반기 6시간 이상** |
| 정기교육 | 그 밖의 근로자(기전·경비·미화) | **매반기 12시간 이상** |
| 관리감독자 교육 | 관리감독자(관리소장 등) | **연간 16시간 이상** |
| 채용 시 교육 | 일반 근로자 | **8시간 이상** (일용·1주 이하 기간제 1시간) |

- 법정 근거 인용은 확실한 것만: 산업안전보건법 제29조(근로자에 대한 안전보건교육),
  시행규칙 별표 4(교육시간)·별표 5(교육내용). **고시 호수·개정 연도는 쓰지 않는다**
  (기존 규칙과 동일 — 개정되면 틀린 근거가 된다).
- 별표 5의 정기교육 필수 포함 항목(LLM 프롬프트에 실을 것): 산업안전 및 사고 예방 ·
  산업보건 및 직업병 예방 · 위험성평가 · 건강증진 및 질병 예방 · 유해·위험 작업환경
  관리 · 산안법령 및 산재보상보험 제도 · 직무스트레스 예방 · 직장 내 괴롭힘, 고객의
  폭언 등으로 인한 건강장해 예방 · **화재·폭발 시 대피 요령 · 폭염·한파 건강장해 예방**
  (최근 추가 항목). 한 회차가 전부를 다룰 필요는 없다 — 반기 여러 회차가 나눠 다룬다.

## 5. 흐름 — "최대한 편리하게"가 요구사항이다

**새 교육일지 (한 화면 폼, 공지문 new와 같은 기둥):**

1. **종류 선택** (카드 3장): 정기교육 / 채용 시 / 관리감독자. 카드에 법정 시간이
   힌트로 보인다("사무직 반기 6시간 · 그 외 12시간").
2. **기본 정보** — 전부 기본값이 채워진 채 시작한다: 교육일자(오늘), 장소("관리사무소"),
   교육시간(1시간), 강사(관리소장 이름 — 결재선/직원에서 가져오되 수정 가능).
3. **주제 선택** (카드 그리드, 공지문 유형 선택과 같은 부품 문법) — §6 카탈로그.
   복수 선택 가능(한 회차에 2~3주제 관행). 자유 입력 칸 하나.
4. **참석자 체크** — 명부 전원이 체크박스로 나온다(기본 전원 체크). 명부가 비어
   있으면 이 자리에서 바로 추가(이름·직종 두 칸). 채용 시 교육은 신입 1명만
   체크하는 사용례.
5. [초안 만들기] → LLM이 교육 내용 작성 → 문서 화면에서 확인·[내용 수정] →
   **[일지 완성]**(오른쪽 sticky 첫 카드)에서 채번 → 인쇄 → 참석자 자필 서명.

**모듈 홈:** 이행 현황 카드(이번 반기 사무직/그 외 정기교육 ✓·미실시, 올해 관리감독자,
반기 마감 D-일) + 일지 목록(DataTable) + [직원 명부] 관리 진입.

**명부 관리:** 이름·직종(사무/기전/경비/미화/기타)·사무직 여부. 퇴사자는 삭제가 아니라
비활성(지난 일지 스냅샷은 어차피 불변이지만, 명부에서 이름이 사라지면 "왜 지웠지"가
된다). [앱 직원 불러오기] 버튼.

## 6. 주제 카탈로그 (약 20종 — 상수 파일, 클라이언트 안전)

각 주제: `key`, `label`, `season`(상반기/하반기/연중), `audience`(전체/기전/경비/미화 힌트),
`hint`(다룰 내용 한 줄). 화면은 현재 반기에 맞는 계절 주제를 앞에 배치한다.

- **계절 — 상반기**: 해빙기 시설물 안전, 봄철 화재 예방, 미세먼지·황사 건강관리,
  장마철 감전·누전 예방, 폭염 대비 온열질환 예방
- **계절 — 하반기**: 태풍·집중호우 대응, 가을철 화재 예방(건조기), 한파 대비 한랭질환
  예방, 동파·제설 작업 안전, 빙판길 넘어짐 예방
- **직무 — 연중**: 전기 작업 안전(기전), 사다리·고소작업 안전, 밀폐공간(저수조·정화조)
  질식 재해 예방, 전동공구·수공구 안전, 근골격계 질환 예방(미화·경비), 청소·소독
  약품(화학물질) 취급 안전, 차량·주차장 사고 예방(경비), 승강기 갇힘·구조 대응,
  응급처치·심폐소생술, 직무스트레스·감정노동(입주민 응대) 관리, 직장 내 괴롭힘 예방,
  화재 대피 요령·소화기 사용법, 산재보상 제도 안내
- **자유 입력**

## 7. LLM 생성 규칙 (시스템 프롬프트에 넣을 것)

- 입력: 교육 종류, 주제(복수), 교육시간, 참석 직종 구성, 단지명. 출력은 **교육 내용만**.
- 출력 스키마(structured outputs):
  ```ts
  {
    // 주제별 절 — heading은 주제명, lines는 "가. 나." 개조식.
    // 강사(관리소장)가 소리 내어 읽으며 교육할 수 있는 구체적 문장으로.
    sections: { heading: string; lines: string[] }[];
    // 마무리 한 줄 (예: "질의응답 및 안전 실천 다짐")
    closing: string;
    needsClarification: string[];
  }
  ```
- 톤: 실무 지시형("~합니다", "~하십시오"가 아니라 "감전 위험이 있는 분전반 작업 전에는
  반드시 차단기를 내리고 검전한다" 같은 개조식 사실 문장).
- 내용은 참석 직종에 맞춘다 — 미화 직원 회차에 분전반 작업 얘기를 넣지 않는다.
- 별표 5 필수 항목 중 주제와 맞닿는 것을 자연스럽게 포함한다(예: 폭염 주제 →
  온열질환 증상·응급조치·물그늘휴식).
- **환각 금지(기존 규칙 계승)**: 입력에 없는 날짜·수치·이름을 만들지 않는다. 법령
  조문·통계 수치는 확실한 것만, 불확실하면 쓰지 않는다. "○○" 빈칸 표기 금지.
- few-shot 2종을 **출력 JSON 그대로** 프롬프트에 넣는다(공지문 방식): ① 정기교육
  (폭염+감전, 그 외 근로자) ② 채용 시 교육(경비 신입). 구현 세션에서 실 API 1건으로
  품질 확인(`*-draft.manual.ts` 패턴).

## 8. A4 서식 (교육일지 표준 구성 — KOSHA·고용부 서식 항목 기준)

```
제목: 안전보건교육 일지          (문서번호는 상단 표 안)
[정보 표] 문서번호 / 교육구분(정기·채용 시·관리감독자) / 교육일시 / 교육장소 /
          교육시간 / 강사(직책·성명)
[교육 내용] 주제별 개조식 (LLM 산출 — 수정 화면에서 고칠 수 있음)
[참석자 명단 표] 번호 · 성명 · 직종 · 서명(빈칸 — 인쇄 후 자필)
[하단] "위와 같이 안전보건교육을 실시하였음." + 작성일 + 강사 서명란 + 관리사무소장 확인란
```

- 활자 11.5~12pt(기안서 축). 참석자 표는 인원수만큼 행 — **참석자 12명 이하 A4 1장
  목표, 넘으면 2장 허용**(쪽 나눔이 표 중간을 자르지 않게). 헤드리스 실측 필수
  (printToPDF pageRanges 판정 — 공지문 모듈 검증법 그대로).
- 서명은 자필 — 전자서명 없음(범위 밖).

## 9. 화면·저장 요약

- `/modules/safety-training` — 이행 현황 카드 + 일지 목록 + 명부 진입
- `/modules/safety-training/new` — §5 폼 (한 화면)
- `/modules/safety-training/[docId]` — A4 미리보기 · [내용 수정](edit 별도 화면) ·
  오른쪽 sticky [일지 완성] 카드 · 폐기(초안=삭제/완성=void, ghost 금지)
- `/modules/safety-training/staff` — 명부 관리
- 저장: `Document { moduleId: "safety-training", type: "safety_training",
  meta: { courseType, date, place, hours, instructor, topics, form, draft(LLM),
  attendees 스냅샷 } }`. 서버 액션 입구마다 세션 → isSubscribed → (생성은) rateLimit.
- 권한: 작성은 전 직원, 수정·폐기는 작성자/마스터(공지문과 동일). 명부 관리는
  마스터+매니저(세대 명부와 같은 축).

## 10. 수용 기준

1. 명부가 있는 상태에서 종류·주제만 고르면(나머지 기본값) **인쇄 가능한 일지 초안**이
   나온다 — 클릭 수 최소가 이 모듈의 존재 이유다.
2. [일지 완성]을 눌러야 `교육-YYYY-####` 채번·확정된다. 초안엔 인쇄가 없다.
3. 완성 후 명부를 수정해도 지난 일지의 참석자 명단은 변하지 않는다(스냅샷).
4. 모듈 홈이 이번 반기 미실시(사무직/그 외 각각)와 올해 관리감독자 미실시를 정확히
   보여준다 — 반기 경계(1/1·7/1) 전후 판정 테스트 포함.
5. `ANTHROPIC_API_KEY` 없으면 "준비 중", 미구독은 서버 액션 입구 차단, 일일 생성 한도.
6. 생성된 교육 내용에 참석 직종과 무관한 내용·지어낸 수치·빈칸(○)이 없다(실 API 1건 확인).
7. A4 실측: 참석자 12명 1장, 20명 2장에서 표가 행 중간에서 잘리지 않는다.
8. tenant 탈퇴 purge가 TrainingStaff를 지운다(테스트).
9. 법정 시간·주기 값은 상수 파일 한 곳에만 있다.
10. `isActive: true` 전환 + 모듈 설명("법정 교육 기록과 기한 알림")이 동작과 일치 —
    "기한 알림"은 모듈 홈 이행 현황 카드가 담당한다(인앱 푸시 알림 아님을 설명 문구가
    과장하지 않는지 확인).
11. 비트리비얼 로직(반기 판정·이행 현황 집계)은 순수 함수로 빼고 `npx tsx *.test.ts`를
    남긴다.
