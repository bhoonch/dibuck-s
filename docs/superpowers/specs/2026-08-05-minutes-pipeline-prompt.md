# 입대의 운영(회의록) 모듈 — 개발 프롬프트

> 이 문서를 새 세션에 그대로 주고 "이 프롬프트대로 구현해줘"라고 하면 된다.
> 구현 전 AGENTS.md와 아래 "먼저 읽을 파일"을 반드시 읽는다.
> 가장 가까운 견본: LLM 호출·draft→완성 채번은 **공지문 모듈**, 외부자 토큰 서명은
> **기안·품의의 `/approve/[token]`**, 추적 테이블은 **DunningEntry**, 파생 공고문은
> **gian Phase 3(`src/lib/gian/notice.ts`)**.

## 1. 목표

소장 고통 2위 **입주자대표회의 대응**을 푼다. 고통은 회의록 작성만이 아니라 네 겹:
① 회의 전 소집 통지·안건 정리·이행 보고 자료 준비(야근), ② 회의 후 회의록 작성
(공동주택관리법상 작성·보관 의무가 있는 법정 서류)·참석 동대표 서명·의결사항 공고
(야근), ③ 의결 후속 이행을 따로 추적하지 않아 다음 회의에서 신뢰 문제, ④ 동대표
교체 시 방침 뒤집힘·고용불안 — 소장의 유일한 방어 수단이 기록이다.

한 줄 정의: **"회의 준비부터 의결 이행까지 한 줄로 잇고, 모든 결정을 소장의 방어
기록으로 남긴다."** 회의록 "생성"만으로는 유료화 근거가 없다(아지트가 AI 작성+녹음
STT 무료 제공 — 경쟁사 분석 확정). 차별점은 파이프라인(소집→기록→서명→공고→추적)과
의결 이력 검색이다.

## 2. 확정된 설계 결정 (재논의 불필요)

- **모듈은 예약돼 있다.** `prisma/seed.ts`의 `id: "minutes"`("AI 회의록 완성",
  ClipboardList, `/modules/minutes`, 월 20,000원, `isActive: false`). 완성 시 true 전환.
  이름·설명은 추적까지 담게 재정의(가칭 "입대의 회의록·의결 관리" — 구현 세션에서
  사용자 확인). 모듈 id는 바꾸지 않는다.
- **동대표 명부는 새로 만들지 않는다** — `Tenant.externalApprovers` 재사용(이미
  회장·감사 + ETC로 이사·동대표). 결재 명부와 회의 명부가 같은 데이터. 필요 시
  JSON 필드 확장(동·호). 참석 체크는 문서 meta 스냅샷(증빙 원칙 — 명부를 나중에
  고쳐도 지난 회의록 불변).
- **회의 = Document 하나가 생애주기를 관통** — 새 type `"minutes"`, `docNoPrefixes`에
  `회의` 추가. 소집(draft, dueDate=회의일) → 회의록 초안(LLM) → **[회의록 완성]에서
  채번**(공지문 `7e2653b` 규칙) → 이후 불변. 소집 통지문은 별도 문서가 아니라 소집
  단계의 인쇄 산출물이다.
- **의결사항은 별도 테이블 `Resolution`** — 참석자(교육일지 meta 스냅샷)와 달리
  의결사항은 완성 후에도 상태가 변한다(이행중→완료). 불변 증빙은 회의록 문서에,
  살아있는 추적은 테이블에. **다음 회의 생성 시 미완료 Resolution이 "전차 회의
  의결사항 이행 보고" 안건으로 자동 제안된다** — 회의 준비 야근을 없애는 핵심 장치.
- **LLM은 회의록 구조화만** — 소장의 수기 메모·녹취 텍스트 붙여넣기 → 안건별
  `{ 논의 요지(개조식), 의결 결과(가결/부결/보류), 찬반 수 }` structured outputs.
  **안건 목록을 앵커로 제공**(자유 작문이 아니라 "이 안건들에 메모를 배분"하는 제약
  과제 — 환각 억제). 입력에 없는 발언·수치·인명 금지(기존 환각 금지 규칙).
  notice-ai 패턴(Sonnet 5·캐싱·`aiEnabled` 게이트·일일 한도).
- **소집 통지문·의결사항 공고문은 결정적 코드** — 정형 문구라 작문이 필요 없다
  (공고문·후속 문서와 같은 판단, 건당 비용 0원). 공고문 파생은 gian Phase 3 동형:
  `meta.sourceDocId` 역링크 + `findNoticeFor` 동형 중복 방지, `notice-paper.tsx` 재사용.
- **전자서명 기본 + 자필 병행 (2026-08-05 사용자 결정, 법적 근거 확인 완료)**
  - 참석 동대표 서명은 **기존 토큰 서명 엔진(`/approve/[token]` — 7일·1회용·재발급
    시 무효) 재사용**이 기본. 회장·감사 외부 결재가 이미 같은 방식으로 판매 중이다.
  - 법적 근거(부록 출처): 전자서명법 제3조(전자 형태라는 이유만으로 효력 부인 불가),
    공동주택관리법 제22조(전자적 방법 의사결정 허용 + 의무관리단지는 전자적 방법
    **우선 이용 노력 의무**), 최근 개정으로 서면에 "실지명의를 확인할 수 있는
    전자서명을 한 전자문서" 포함. 회의록 서명 요구 자체는 법이 아니라 시·도 준칙·
    관리규약에서 나온다(서울 준칙: 참석 동별 대표자 서명 + 3일 이내 관리주체 통보).
  - **증거력 3장치가 필수 조건이다**: ① 서명 기록 저장(서명 시각·발송 연락처·서명
    시점 문서 버전 해시) + 완성 회의록 A4 하단에 서명 기록 표(성명·일시·방식) 인쇄
    ② **서명이 시작되면 회의록 수정 불가**(결재 시작 후 수정 불가 규칙과 동형 —
    서명 후 내용이 바뀌면 증거력이 무너진다) ③ "관리규약의 회의록 서명 방식을
    확인하세요" 안내 1줄 — 판정은 하지 않는다(법 해석은 코드가 하지 않는다).
  - 자필 경로 병행: 인쇄 서식에 서명란 — 자필을 요구하는 규약인 단지가 고른다.
  - 휴대폰 본인인증(PASS 등)으로 "실지명의 확인"을 강화하는 것은 **범위 밖** —
    건당 비용이 발생하므로 분쟁 사례·수요 확인 후.
- **소집 통지 기한은 단지 설정값**(기본 5일, "관리규약을 확인하세요" 힌트) —
  관리규약이 정하는 값이라 코드가 판정하지 않는다. D-day 인앱 알림.
- **범위 밖 (다시 검토하지 말 것)**: 녹음 STT(아지트 무료 — 유료 차별점 아님,
  v1은 텍스트 붙여넣기) / 전자투표(이지스 무료 — 기존 보류 목록) / K-apt 공개 입력
  (API 미확인 — S-APT 보류와 같은 판단) / 휴대폰 본인인증(위).

## 3. 스키마

```prisma
model Resolution {
  id             String    @id @default(cuid())
  tenantId       String
  meetingDocId   String    // 의결한 회의 문서
  order          Int
  title          String
  decision       String    // 가결 | 부결 | 보류
  followupStatus String    // 없음(단순 의결) | 이행중 | 완료
  dueDate        DateTime?
  note           String?
}
```

- ⚠️ meetingDocId가 Document를 참조한다 — **초안 하드 삭제 시 Resolution 처리
  (cascade 또는 가드)를 명시적으로 설계**할 것(DunningEntry cascade 마이그레이션
  `20260731162935`가 선례). 완성 전에는 Resolution이 없으므로(완성 시 등록) 실제로는
  초안 삭제와 충돌하지 않지만, 완성본 void 시 Resolution을 어떻게 할지(남긴다 —
  의결은 유효, 문서만 폐기)를 코드 주석으로 박아둘 것.
- 서명 기록: `ApprovalStep` 재사용이 가능한지 먼저 검토(외부 결재자 이름 스냅샷·토큰
  발급이 이미 있다). 결재(순차)와 서명(병렬 — 순서 없음)의 차이가 커서 안 맞으면
  meta 또는 경량 테이블로. **구현 세션에서 판단하되, 병렬 서명이라는 차이를 근거로
  기록할 것.**
- Document meta: `{ meetingAt, place, attendees 스냅샷, agenda: [...], draft(LLM),
  signatures: [...], noticeDocId? }`.
- tenant 탈퇴 purge(`tenant-deletion.ts`)에 Resolution deleteMany 추가.

## 4. 흐름

**① 회의 만들기 (5분)** — 일시·장소, 참석 대상 명부 전원 기본 체크, 안건(미완료
Resolution 자동 제안 + 자유 추가 + 첨부). → [소집 통지문 인쇄](결정적 코드, A4
게시판용). 통지 기한 D-day 알림.

**② 회의 직후 (10분)** — 메모·녹취 텍스트 붙여넣기 → LLM 구조화 → 안건별 초안.

**③ 검토 → [회의록 완성]** — 수정 화면에서 다듬고 완성 → `회의-YYYY-####` 채번.
완성 시 의결 결과를 Resolution으로 등록 — **확인 UI를 거친다**(LLM 출력을 그대로
DB에 넣지 않는다).

**④ 서명** — [서명 요청] → 참석 동대표에게 토큰 링크(메일, SMTP 없으면 링크 복사
버튼 — 카카오톡으로 직접 전달). 서명 화면은 회의록 전문 + [서명] 버튼. 병렬 —
순서 없음. 전원 서명 시 문서에 서명 완료 표시. 자필 경로: 그냥 인쇄하면 서명란이
빈칸으로 나온다.

**⑤ [입주민 공고문 만들기]** — 완성 문서에서 1클릭 파생(결정적 코드).

**⑥ 이행 추적** — 모듈 홈 미이행 목록(기한 경과 빨강), 상태 변경 한 클릭, 다음
회의 안건 자동 제안으로 사이클이 닫힌다.

## 6. A4 서식 2종 (결정적 코드)

**소집 통지문**: 제목(제N차 입주자대표회의 소집 통지) / 일시·장소 / 안건 목록 /
관리규약 근거 문구 / 명의(입주자대표회의 회장 — `externalApprovers`의 회장,
없으면 관리사무소장). 게시판용이라 활자 크게(공고문 축 14pt).

**회의록**: 제목 / [정보 표] 문서번호·회차·일시·장소·참석(재적 N·참석 N) /
안건별 — 논의 요지(개조식)·의결 결과(가결/부결/보류, 찬반 수) / [하단] 참석자
서명 표(성명·서명 — 전자서명 완료 시 서명 기록(일시·방식), 미서명은 빈칸=자필란).
책상 증빙 문서라 기안서 축(11.5~12pt), `gian-paper.tsx` 괘선 문법. 헤드리스 실측
(printToPDF — 공지문 검증법).

## 9. 수용 기준

1. 미완료 의결이 있는 상태에서 새 회의를 만들면 이행 보고 안건이 자동 제안된다.
2. 메모 붙여넣기 → 안건별 구조화 초안. 입력에 없는 발언·수치·인명이 없다(실 API
   1건 확인, `*-draft.manual.ts` 패턴).
3. [회의록 완성]에서만 `회의-YYYY-####` 채번. 완성 시 Resolution이 확인 UI를 거쳐
   등록된다 — LLM 출력이 무확인으로 DB에 들어가지 않는다.
4. **서명이 하나라도 되면 회의록 수정이 잠긴다.** 서명 기록(시각·연락처·문서 해시)이
   저장되고 A4 하단에 인쇄된다. 토큰은 1회용·만료·fail-closed(테스트).
5. 서명 요청 없이 인쇄하면 서명란이 빈칸(자필 경로)으로 나온다 — 전자·자필이 한
   서식에서 공존한다.
6. 공고문 파생은 1클릭·중복 방지·역링크(gian Phase 3 동형). 파생 실패가 완성을
   롤백하지 않는다.
7. 의결사항 대장에서 키워드 검색 → 의결 회의 문서번호·날짜가 나온다.
8. `ANTHROPIC_API_KEY` 없으면 생성만 "준비 중", 소집·서명·추적·공고 파생은 전부
   돈다(결정적 코드). 미구독 입구 차단, 일일 생성 한도.
9. tenant 탈퇴 purge가 Resolution을 지운다(테스트). 완성본 void 시 Resolution은
   남는다(의결은 유효 — 주석으로 근거 명기).
10. 비트리비얼 로직(안건 자동 제안·서명 상태 전이)은 순수 함수 + `npx tsx *.test.ts`.
11. 시드 이름·설명이 실제 동작과 일치(과장 금지).
