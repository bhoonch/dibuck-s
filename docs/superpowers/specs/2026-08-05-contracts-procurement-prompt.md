# 사업자 선정·계약 대장 모듈 — 개발 프롬프트

> 이 문서를 새 세션에 그대로 주고 "이 프롬프트대로 구현해줘"라고 하면 된다.
> 구현 전 AGENTS.md와 아래 "먼저 읽을 파일"을 반드시 읽는다.
> 견본: 역산 엔진·크론 회차 키는 **법정점검 대장 스펙**(2026-08-05-legal-inspection-
> prompt.md)의 주기 엔진 문법, 금액 판정은 **`src/lib/gian/rules.ts`** 재사용.
> **LLM 없음** — 공고문 초안까지 정형 서식이라 결정적 코드로 충분하다.

## 1. 목표

소장 고통 5위 **사업자 선정·계약 관리**를 푼다. 사업자 선정은 소장 업무 중 유일하게
"절차 자체가 법정"인 업무다 — 국토부 「주택관리업자 및 사업자 선정지침」(고시)이
공고 기간·방식·의결·낙찰 순서를 정하고, 공동주택 감사의 단골 지적이 정확히 여기다.

고통 세 겹: ① 절차 지뢰밭 — 전자입찰(K-apt) 의무, 공고 기간(입찰서 마감 전일 기산
10일), 수의계약 한도, 하나만 어긋나도 감사 지적·재공고·계약 공백 ② **역산 실패가
사고의 형태** — 만료일을 알아도 늦다. 의결→공고 10일→심사→체결을 역산하면 두 달
전에 움직여야 하는데 그 시점을 알려주는 것이 없다 ③ 금액이 걸려 입주민·입대의에겐
유착을, 업체에겐 불공정을 의심받는다 — 유일한 방어는 절차를 지켰다는 기록인데
공고 캡처·회의록·심사표로 산재한다.

한 줄 정의: **"만료일에서 역산해 '지금 시작'을 알려주고, 선정 절차의 매 단계를
증빙과 함께 기록해 감사·의심 양쪽에 내밀 서류철을 만든다."**

로드맵 2번의 재정의("만료 알림 + K-apt 입찰 리드타임 역산 — 만료일만 알리면 이미
늦다") 그대로다. 조사 범위 내 경쟁사 중 리드타임 역산을 하는 곳은 없었다(저난이도
고체감 — 경쟁사 분석 2026-07-27).

## 2. 확정된 설계 결정 (재논의 불필요)

- **모듈은 예약돼 있다.** `prisma/seed.ts`의 `id: "contracts"`("계약 만료 알리미",
  FileText, `/modules/contracts`, 월 20,000원, `isActive: false`). **이름을 재정의
  한다**(가칭 "사업자 선정·계약 대장" — 구현 세션에서 사용자 확인). "만료 알리미"는
  이 범위를 못 담는다. id·가격 유지, 완성 시 true.
- **계약 = Document, 별도 마스터 테이블 없음** — 홈 할 일 위젯 "계약 만료 D-30"의
  집계 컨벤션이 이미 `type:"contract"`+dueDate를 전제한다(safety-training 스펙에도
  "계약 전용"으로 명기). 계약서는 그 자체가 증빙 문서다(첨부·채번·검색). 새 type
  `"contract"`, `docNoPrefixes`에 `계약` 추가, **dueDate=만료일**, 채번은 등록 즉시
  (수선 기록과 같은 판단 — 초안·작문 단계가 없다).
  - meta: `{ vendor, amount, category(공사|용역|위탁관리|기타), startAt, endAt,
    method(경쟁입찰|수의계약), previousDocId(갱신 사슬), procurement? }`.
- **갱신 절차 = 새 draft 계약 문서의 `meta.procurement`** — 방식별 단계 템플릿의
  **스냅샷**: `[{ key, label, deadline?, doneAt?, attachDocId?, note }]`.
  - 경쟁입찰 템플릿: 선정지침 확인 → 입대의 의결(공고안) → K-apt 공고(마감 전일
    기산 10일) → 개찰·적격심사 → 낙찰 결과 공개 → 계약 체결 → 계약서 보관.
  - 수의계약 템플릿: 사유 확인 → 견적 비교 → 의결 → 체결.
  - **항목은 카탈로그가 주지만 단계 완료 판정은 사람이 한다** — 선정지침 해석을
    코드가 하지 않는다(전결 한도·교육시간 규정과 같은 원칙). 지침이 개정돼도 지난
    절차 기록은 불변(스냅샷). 전 단계 완료 시 새 계약 확정(채번)·구 계약과 양방향
    링크(`findFollowupFor` 동형 중복 방지).
- **역산 엔진은 순수 함수** — 만료일·방식에서 각 단계의 "늦어도 이 날"을 계산.
  공고 기간(마감 전일 기산 10일)은 지침의 확정 값이라 코드가 계산하고, 의결 준비·
  심사·체결 버퍼는 **단지 설정값**(기본값 제공 — 관리규약 통지 기한과 같은 구조).
  KST(`ymdKst` 축)·경계 테스트 필수. **확정 값은 상수 한 곳**(`src/lib/contracts/
  catalog.ts` — 개정 대비, ⚠️ 고시는 법률보다 개정이 잦다).
- **수의계약/경쟁입찰 힌트는 `gian/rules.ts` 재사용** — VAT /1.1 환산 후 500만원
  비교가 이미 구현·테스트돼 있다. 금액 입력 시 힌트 배지로 표시. **판정 로직을
  복사하지 말고 import** — 두 벌이 되는 순간 한쪽이 거짓말을 시작한다.
- **크론 알림 사다리**: `/api/cron/contracts` — CRON_SECRET, **GET·POST 둘 다**,
  하루 1회. ① 갱신 시작 기한(역산 결과) ② 공고 기한 임박(경쟁입찰 진행 중) ③ 만료
  D-30·D-7 ④ 만료 경과·절차 지연 — 빨간 배지 + 소장 메일(`trySend`, 계약 공백은
  접속 안 해도 닿아야 한다). 회차 키 `contract_{docId}_{단계}_{기한Ymd}`, 판정은
  "임계를 처음 넘긴 때". **구독 단지만**(미구독 알림은 거짓 약속).
- **절차 경과 보고 A4 = 투명성 출력물** (결정적 코드) — 공고 일자·기간, 응찰 수,
  심사·낙찰 경과, 의결 일자를 한 장으로. 입대의 보고·게시판 공개용. 앞 스펙들의
  방어 기록(의결 대장·이력 카드)과 같은 축 — 이 모듈의 "양쪽 의심" 고통에 대한 답.
- **범위 밖 (다시 검토하지 말 것)**: K-apt 연동(공개 API가 공고·기본정보 조회용만
  확인 — 로드맵 확정. 공고 게시는 K-apt에서, 디벅은 일정·증빙 관리. 조회 API가
  쓸 만하면 "공고 등록 확인" 자동 체크를 후속으로) / 적격심사 점수 계산(심사는
  심사위원 판단, 배점표는 단지·공종마다 다름 — 계산기를 넣는 순간 "디벅이 심사
  했다"는 책임이 생긴다. 심사표는 첨부로) / 전자계약·보증보험 검증(외부 인프라
  의존 — 첨부로 시작) / LLM.

## 3. 흐름

**① 계약 등록 (도입 시 일괄 + 이후 건별)** — 계약명·업체·기간·금액·분류·방식·
계약서 스캔 첨부. 금액 입력 시 수의계약/경쟁입찰 힌트. 등록 즉시 `계약-YYYY-####`
채번, dueDate=만료일 → 홈 위젯이 그대로 붙는다.

**② 역산 타임라인** — 계약 상세에서 "이 계약을 갱신하려면": 오늘 기준 각 단계의
늦어도-이-날이 세로 타임라인으로. 시작 기한이 지나면 빨강.

**③ [갱신 절차 시작]** — 방식 선택 → 단계 체크리스트 생성(스냅샷). 단계마다
완료일 기록·증빙 첨부·메모. 진행 중 절차는 모듈 홈 상단에 노출.

**④ 절차 완료 → 새 계약 확정** — 낙찰 업체·금액·기간 입력 → 채번 → 구 계약과
사슬 링크. 구 계약은 "갱신됨" 상태로.

**⑤ [절차 경과 보고 인쇄]** — 완료된 절차에서 1클릭 A4.

## 7. 수용 기준

1. 계약 등록만 하면 — 선정지침을 몰라도 — 역산 타임라인과 "지금 시작" 알림이 나온다.
2. 등록 즉시 `계약-YYYY-####` 채번, 홈 할 일 위젯 "계약 만료 D-30"에 뜬다(기존
   컨벤션 무수정 또는 최소 수정 — 수정했다면 근거 기록).
3. 금액 입력 시 수의계약/경쟁입찰 힌트가 `gian/rules.ts` **import**로 나온다 —
   판정 로직 중복 없음(grep으로 확인 가능해야 한다).
4. 갱신 절차의 단계 체크리스트는 시작 시점 스냅샷 — 이후 템플릿(카탈로그)을 고쳐도
   진행 중 절차가 변하지 않는다.
5. 전 단계 완료 시에만 새 계약 확정·채번. 구 계약과 양방향 링크, 중복 확정 방지
   (조건부 updateMany).
6. 크론 알림 4종이 회차 키로 중복 없이 나가고, 크론이 하루 빠져도 다음 실행에서
   잡힌다. 만료 경과는 소장 메일(SMTP 없으면 조용히 생략).
7. 절차 경과 보고 A4가 공고·심사·의결 경과를 한 장으로 그린다(실측 — 표가 행
   중간에서 잘리지 않는다).
8. 역산 순수 함수 테스트에 KST 경계·마감 전일 기산·버퍼 설정값 반영 포함.
9. LLM 호출·`ANTHROPIC_API_KEY` 의존이 코드에 없다.
10. tenant 탈퇴 purge 영향 없음 확인(신규 테이블 없음 — Document는 기존 purge가
    담당). 미구독 입구 차단, 크론은 구독 단지만.
11. 시드 이름·설명이 실제 동작과 일치(과장 금지 — "역산 알림"이 크론 실동작 범위).
