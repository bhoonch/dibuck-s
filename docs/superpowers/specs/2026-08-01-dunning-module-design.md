# 미납 독촉장 자동완성 모듈 — 설계

2026-08-01 확정. 로드맵 1번. 시드에 예약된 `dunning` 모듈(월 30,000원, `/modules/dunning`, 현재 `isActive: false`)의 구현 설계.

## 목적

관리사무소가 미납 세대 데이터(엑셀 또는 직접 입력)만 넣으면 **1차 독촉장 → 2차 최고장 → 3차 내용증명**을 자동 완성하고, 세대별 A4 용지를 일괄 인쇄한다. 같은 세대의 발송 이력을 추적해 다음 회차에서 **다음 단계 문서를 자동 제안**한다 — 건당 과금 B2C 내용증명 서비스(참지마요·콩밥 등)에 없는, "매달 반복 발송하는 관리사무소" 시나리오가 차별점.

## 결정 사항 (인터뷰 확정)

| 항목 | 결정 |
|---|---|
| 문서 범위 | 3단계 전부 (독촉장·최고장·내용증명) |
| 데이터 입력 | 엑셀 업로드 + 직접 입력 둘 다 |
| 내보내기 | A4 일괄 인쇄 + 우체국 편지병합용 수신인 엑셀. 이메일은 범위 외 |
| 본문 생성 | 정형 템플릿(결정적 함수). LLM 사용 안 함 |
| 구조 | A안 — 문서함 통합 + 발송 이력 테이블 |

## 1. 데이터 모델 (스키마 변경 1개)

```prisma
model DunningEntry {          // 발송 1건 = 세대 1행
  id        String    @id @default(cuid())
  tenantId  String
  docId     String              // 소속 발송 회차(Document)
  dong      String
  ho        String
  name      String?             // 엑셀에 없으면 세대명부(Unit)에서 자동 매칭
  amount    Int                 // 미납액(원)
  period    String?             // 미납 기간 자유 텍스트 "2026년 3월분 ~ 6월분"
  stage     Int                 // 1 독촉장 · 2 최고장 · 3 내용증명
  paidAt    DateTime?           // 납부 확인 — 문서는 불변, 상태는 여기만 바뀐다
  createdAt DateTime  @default(now())
  @@index([tenantId, dong, ho])
}
```

- 미납 기간은 **자유 텍스트** — 회계 프로그램마다 export 형식이 제각각이라 구조화(시작월·종료월)는 파싱 실패만 만든다.
- 단계 승격 판정: `(dong, ho)`별 최신 엔트리에 `paidAt`이 없으면 `min(stage + 1, 3)` 제안. 쿼리 하나.
- 납부 표시는 엔트리에만 찍는다. 확정 문서(`Document.meta`)는 수정하지 않는다.

## 2. 문서함 통합

- 발송 회차 1개 = `Document` 1건. type `dunning_letter`(채번 접두어 `독촉-` 이미 `documents.ts`에 등록됨).
- 공고문처럼 **생성 즉시 final·즉시 채번, 결재선 없음** — 관리사무소장 명의 문서.
- 제목 예: "미납 관리비 독촉장 — 2026년 7월 (12세대)".
- 한 회차에 1·2·3차 세대가 섞여도 문서는 하나. 세대별 용지가 각자 단계의 문안으로 나온다.
- `Document.meta`에는 회차 공통값(납부기한·납부계좌·발송일 등) 스냅숏 저장. 세대 행은 `DunningEntry`가 원본.
- 문서함(`/documents`) type 필터에 "독촉장" 추가.

## 3. 화면 (`/modules/dunning`, 구독 가드 `isSubscribed(tenantId, "dunning")`)

- **홈** — SummaryBox(미납 세대수·총 미납액·단계별 분포) + 발송 회차 목록(DataTable) + [새 독촉장]. **재발송 검토 대상**(마지막 발송 후 30일 경과·미납) 목록 표시 — 크론 없이 조회 시점 계산.
- **새 독촉장 — 마법사 3걸음**
  1. **입력**: 엑셀 업로드(양식 다운로드 제공) 또는 표 직접 입력. 동·호만 있으면 세대명부에서 이름 자동 매칭.
  2. **확인**: 세대별 단계 자동 제안 + 개별 조정, 납부기한·납부계좌 입력.
  3. **미리보기 → 생성**.
- **회차 상세** — 세대 목록(납부 확인 체크), PaperScale 미리보기, [전체 인쇄], [우체국 발송용 수신인 엑셀](내용증명 세대 있을 때).

## 4. 문안 (`templates.ts` — 정형 템플릿, 결정적 함수)

- **1차 납부 안내·독촉장**: 정중한 안내 + 미납 내역 + 납부기한 + 계좌.
- **2차 최고장**: 경고 톤 + 연체요율·관리규약 근거 + 미이행 시 조치 예고.
- **3차 내용증명**: 발신인·수신인 주소 블록(우체국 요건), 최종 최고 + 지급명령 등 법적 절차 예고. 화면에 "인쇄 후 우체국 3부 제출" 안내.
- 용지: `NoticePaper` 문법을 따르는 **`DunningPaper`** — 세대당 A4 1쪽, `break-after: page`로 N세대 일괄 인쇄. 하단 단지명·관리사무소장 명의 + 직인(공고문과 동일 자산). 활자는 우편물 기준(기안서급 11.5pt 계열 — 게시물 14pt 아님).

## 5. 엑셀

- **업로드**: `settings/actions.ts`의 `uploadUnits` 패턴 복제 — 동적 `import("xlsx")`, 5MB 제한, 헤더행 자동 판별. 열: 동·호·미납액 필수, 이름·기간 선택.
- **양식**: `public/dunning-upload-sample.xlsx` 정적 파일.
- **우체국 내보내기**: 내용증명(3차) 세대의 수신인 목록 엑셀(성명·주소=단지주소+동·호) 생성 — `XLSX.write`, 새 의존성 없음. ⚠️ 인터넷우체국 편지병합 양식의 정확한 열 구성은 **구현 시점에 실물 확인**(양식이 바뀌는 곳이라 지금 박제하면 거짓말이 된다). 단지 주소가 Tenant에 있는지도 구현 때 확인.

## 6. 범위 외

- **이메일 발송** — 세대 명부(`Unit`)에 이메일 필드가 없고 실무 수집도 드묾. 명부 확장 때 재검토(mailer는 이미 있어 붙이기 쉽다).
- **자동 재발송 크론** — 발송은 "인쇄해서 부치는" 사람 행위라 자동화 불가. 홈의 재발송 검토 목록으로 갈음.
- **알림 발송** — 본인이 만든 문서의 알림은 소음.
- **납부 연동(회계 데이터 자동 대사)** — 데이터 소스가 없다. 납부는 수동 체크.

## 7. 검증

- 단위 테스트: 문안 빌더, 단계 승격 판정, 엑셀 파서.
- A4 넘침은 헤드리스 스크린샷 실측(독립 HTML) — 산술 추정 금지.
- 완료 시 시드 `isActive: true`로 모듈 공개(라우트 구현 전엔 켜지 않는다는 시드 주석 준수).
