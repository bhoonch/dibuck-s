# 공지문(공고문·안내문) 자동완성 모듈 — 개발 프롬프트

> 이 문서를 새 세션에 그대로 주고 "이 프롬프트대로 구현해줘"라고 하면 된다.
> 구현 전 AGENTS.md와 아래 "먼저 읽을 파일"을 반드시 읽는다.

## 1. 목표

관리사무소 직원이 **유형을 고르고 키워드 몇 개(일시·대상·사유)만 입력하면**,
게시판·엘리베이터에 붙일 A4 공고문·안내문이 완성된다.
셀프서비스 SaaS 원칙: 운영자 개입 없이 사용자 혼자 끝난다.

경쟁 현황(2026-08 조사): 아파트너는 공지 "게시·푸시"만 하고 문안 작성은 사람 몫이다.
문안 자동완성이 이 모듈의 차별점이다.

## 2. 확정된 설계 결정 (재논의 불필요)

- **모듈은 이미 예약돼 있다.** `prisma/seed.ts`에 `id: "notice"`, route `/modules/notice`,
  `isActive: false`. 데모 단지가 구독 중이고 시드 문서(`공지-2026-0001`, 단수 안내문)도 있다.
  구현 완료 시 `isActive: true`로 전환하고, 모듈 설명 문구가 실제 동작과 일치하는지 확인한다.
- **결재 후속 공고문과의 관계**: `src/lib/gian/notice.ts`(moduleId `approvals`)는 그대로 둔다.
  `Document.type`은 둘 다 `"notice"`를 쓰고 **moduleId로 출처를 구분**한다.
  채번은 `nextDocNo`가 tenantId+type 기준이라 `공지-YYYY-####` 한 시퀀스로 자동 통합된다 —
  의도된 동작이다(한 단지의 공지 대장은 하나).
- **목록 화면은 type `"notice"` 전체**를 보여준다(결재 파생 공고문 포함 — 파생본에는
  원본 기안 역링크 칩, 기존 목록 패턴 참고). 생성·수정·폐기는 이 모듈이 만든 문서만.
- **흐름**: 유형 선택 → 공통 입력 4칸 → LLM 생성 → A4 미리보기·인라인 수정 → 저장 → 인쇄.
- **생성은 Claude API** — `src/lib/gian/claude.ts` 패턴을 그대로 따른다:
  Sonnet 5, structured outputs(파싱 실패 없음), 고정부 프롬프트 캐싱,
  `aiEnabled()` 게이트(키 없으면 모듈 화면 "준비 중"), 오늘 날짜는 user turn에.
- **문서 격은 두 가지**: 안내문(협조 요청 톤)과 공고문(격식·공고번호·"~을 공고합니다").
  유형 카탈로그가 격을 정한다.
- **출력은 A4 게시용 인쇄만.** 발송(메일·문자) 없음 — 나중 일감.
- **파생·후속 문서 없음.** 단문 문서라 wizard도 과하다 — 폼 한 장이면 된다.

## 4. 유형 카탈로그

상수 하나로 정의한다(`src/lib/notice-catalog.ts` 등 — `src/lib/gian/notice.ts`,
`src/lib/announcements.ts`와 혼동되지 않는 이름으로).
각 유형: `key`, `label`, `category`, `kind`("guide" 안내문 | "official" 공고문),
`hint`(입력 placeholder 예시).

**입력 폼은 전 유형 공통 4칸** — 유형별 필드 스키마를 만들지 않는다(ponytail):

1. 일시·기간 (자유 텍스트 — "8월 10일(월) 10:00~16:00", "8월 둘째 주")
2. 대상·구역 (자유 텍스트 — "전 세대", "101동", "지하주차장 1층")
3. 내용·사유 키워드 (멀티라인 — 사유, 협조사항, 강조할 것)
4. 문의처 (기본값: 관리사무소, 단지 설정에 전화가 있으면 채워 넣음)

카테고리·유형 (총 25종 + 자유 입력):

- **시설·점검**: 단수 안내, 정전 안내(전기설비 정기점검), 승강기 정기점검, 저수조(물탱크) 청소,
  소독·방역 실시, 정화조·배수관 청소, 공용부 공사 안내, 조경(전지·소독) 작업
- **생활·질서**: 주차 질서 협조, 장기 방치 차량 이동 안내, 층간소음 자제, 금연구역 안내,
  재활용품 분리배출, 음식물쓰레기 배출, 쓰레기 무단투기 경고, 복도·계단 적치물 정리, 반려동물 관리
- **계절·안전**: 동파 예방(동절기), 태풍·호우 대비, 폭염 대비, 화재 예방, 제설·빙판 주의
- **행사·운영**: 명절 인사 및 휴무 안내, 알뜰장터·행사 안내, 관리비 관련 안내,
  입주자대표회의 개최 공고 **(official)**, 동별 대표자 선출 공고 **(official)**
- **자유 입력**: 유형 없이 키워드만으로 — kind는 사용자가 토글

## 5. LLM 시스템 프롬프트에 넣을 서식 규칙

안내문(guide) 정형 — 관리사무소 실무 표준:

```
제목 (예: "단수 안내")
인사말 한 줄 ("입주민 여러분 안녕하십니까." + 사유 도입)
■ 개요 항목: 일시 / 대상(구역) / 사유 — 입력값 그대로
■ 협조 사항: 입주민이 할 일 (유형별 실무 지식으로 보강 — 예: 단수 전 물 받아두기,
  단수 해제 직후 녹물 2~3분 흘려보내기, 소독 시 창문 닫기)
맺음 협조 문구 ("입주민 여러분의 양해와 협조를 부탁드립니다.")
게시일 / "○○아파트 관리사무소장"
```

공고문(official) 정형:

```
"○○아파트 공고 제2026-○호" (호수는 docNo에서 유도, LLM이 짓지 않는다)
제목
"...에 따라 다음과 같이 공고합니다." 도입
개조식 본문 (가. 나. 다.)
게시일 / "○○아파트 관리사무소장" (직인 자리)
```

환각 금지 — `gian/claude.ts`의 규칙을 그대로 계승한다:

- 입력에 없는 날짜·수치·업체명을 만들지 않는다. 필요하면 `needsClarification`에 적는다.
- **"○월 ○일" 빈칸 날짜는 어떤 경우에도 쓰지 않는다.** 입력된 일정 표현은 다듬지 말고 그대로.
- 법적 근거는 확실할 때만 (예: 저수조 청소 = 수도법 제33조 반기 1회). 불확실하면 쓰지 않는다.
- 톤: 정중하고 협조 요청형. 실무 조사 결과 "민원의 80%는 공사 자체가 아니라 사전 고지
  태도에서 나온다" — 경고형 유형(무단투기 등)도 위협조가 아니라 협조 요청으로 쓴다.

## 7. 출력 스키마 (structured outputs)

```ts
{
  title: string;
  kind: "guide" | "official";      // 카탈로그 값을 주입하고 LLM은 받아 적는다
  intro: string;                    // 인사말·도입 (official이면 "...공고합니다" 문장)
  items: { label: string; value: string }[];  // ■ 개요 항목 — 입력값 그대로
  bodyLines: string[];              // 협조 사항 / 개조식 본문
  closing: string;                  // 맺음 문구 (official이면 빈 문자열 허용)
  needsClarification: string[];
}
```

결정적 값(단지명·게시일·공고 호수·문의처)은 코드가 계산해 주입한다 — LLM이 짓지 않는다.

## 8. 화면·저장

- `/modules/notice` — 목록: docNo·제목·유형·상태·게시일. type `"notice"` 전체
  (결재 파생본은 원본 역링크 칩). 저장값은 폼 위에 먼저 보이는 기존 규칙 준수.
- `/modules/notice/new` — 카테고리별 유형 그리드 → 공통 입력 4칸 → 생성.
- `/modules/notice/[docId]` — A4 미리보기 + 인라인 수정 + 인쇄 + 폐기(**폐기 버튼 ghost 금지**).
- 저장: `Document { moduleId: "notice", type: "notice", meta: { form, draft, kind, typeKey } }`.
  meta에 폼 입력과 LLM 출력 원본을 보관한다(재편집의 원천 — 기안 모듈과 동일).
  자식 테이블을 추가하게 되면 FK는 반드시 `onDelete: Cascade`(purge).
- 서버 액션 입구마다: 세션 → `isSubscribed(tenantId, "notice")` → `rateLimit` 일일 한도.
  검사는 호출자가 아니라 **함수 자기 입구에서** (AGENTS.md).
- 게시용 활자: 읽는 거리 규칙 — 공고문·안내문은 본문 14pt급. Pretendard는 저장소 안 자산.

## 9. 수용 기준

1. 유형을 고르고 일시·구역·사유 세 가지만 입력하면 **수정 없이 인쇄 가능한** 완성문이 나온다.
2. `ANTHROPIC_API_KEY` 미설정이면 모듈 화면이 "준비 중"을 안내한다 (기안 모듈과 같은 규칙).
3. 미구독 단지는 서버 액션 입구에서 차단된다 (화면 밖 직접 호출 포함).
4. 일일 생성 한도가 동작한다.
5. 결과물에 입력에 없는 날짜·수치·빈칸("○월 ○일")이 없다.
6. A4 1장을 넘치지 않는다 — 산술 추정 말고 **독립 HTML + 헤드리스 스크린샷으로 실측**.
7. 결재 후속 공고문 흐름(`gian/notice.ts`)이 깨지지 않는다 — 채번·목록 정합 확인.
8. `isActive: true` 전환 시 모듈 설명 문구("상황만 고르면 공지문 초안이 완성돼요")가
   실제 동작과 일치한다. 동작과 문구가 어긋나면 같은 커밋에서 고친다.
9. 비트리비얼 로직(카탈로그 조회·docNo 정합 등)에 실행 가능한 검증 하나를 남긴다
